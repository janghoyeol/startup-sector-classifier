# 0002. 자모 단위 토크나이저

## 상태
승인됨 (2026-10-22)

## 배경
한글 음절(가, 힣 등)은 초성·중성·종성의 조합이다. 일반적인 서브워드(BPE) 토크
나이저는 학습 코퍼스에 없던 조합(신조어, 오타, 줄임말)을 만나면 어색하게
쪼개지는데, 아예 자모 단위로 분해해서 학습하면 어휘 수가 작아지고(임베딩
테이블이 줄어 같은 파라미터 예산 안에서 모델을 더 깊게 쌓을 여유가 생김),
처음 보는 글자 조합에도 원리적으로 강건하다.

## 결정
유니코드의 NFD(정준 분해) 정규화를 그대로 활용한다. `unicodedata.normalize
("NFD", text)`를 거치면 모든 한글 음절이 자동으로 초성(U+1100~1112, 19개)
·중성(U+1161~1175, 21개)·종성(U+11A8~11C2, 27개) 결합자모 시퀀스로 풀리고,
NFC로 되돌리면 정확히 복원된다. 직접 산술 분해 공식을 짤 필요가 없다 —
"자모를 직접 설계"했다고 할 때의 핵심은 이 구조를 활용해 어휘를 작게
설계했다는 것이지, 이미 표준화된 유니코드 분해 알고리즘을 재발명하는 게
아니다.

어휘 구성:
- 특수 토큰 4개: [PAD] [UNK] [BOS] [EOS]
- 한글 자모 67개(19+21+27): 코퍼스 등장 빈도와 무관하게 항상 포함 —
  자모는 전체 한글을 표현하는 데 필요한 "알파벳"이라 드물게 등장해도 빠지면
  안 됨
- 기타 문자(영문·숫자·문장부호 등): 코퍼스에서 일정 빈도(`min_freq`) 이상
  등장한 것만 포함, 나머지는 [UNK]

## 검증
실제 수집 데이터 샘플 2건으로 인코딩→디코딩 왕복 테스트, 100% 원본 복원
확인 (`tests/test_tokenizer.py`). 짧은 샘플 기준 어휘 크기 101, 전체
코퍼스로는 150~200 수준일 것으로 예상 — GPT-2의 50,257 같은 서브워드 어휘와
비교하면 훨씬 작다.

## 트레이드오프
- 시퀀스 길이가 음절 단위보다 1.6~1.9배 길어짐 (샘플 기준) → 같은 문맥
  길이를 커버하려면 더 긴 context window가 필요하거나, attention 비용이
  늘어남. 사전학습 설계 시 이 점을 반영해야 함.
- 드문 비한글 문자(희귀 한자, 특수기호 등)는 [UNK]로 손실 — 영어 고유명사
  등은 코퍼스 등장 빈도에 따라 자모 수준이 아니라 글자 단위로 통째로
  어휘에 들어가므로 큰 문제는 아님 (실제 샘플에 "Michael Brian Young" 같은
  영문 고유명사도 왕복 복원 100% 확인됨).
