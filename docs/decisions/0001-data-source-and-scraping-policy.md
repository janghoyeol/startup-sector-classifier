# 0001. 데이터 소스와 수집 정책

## 상태
승인됨 (2026-10-21)

## 배경
처음에는 thevc.kr(스타트업 디렉토리)에서 회사 소개글 + 업종 태그를 수집하려 했다.
robots.txt는 일반 크롤러를 허용했지만:

- 실제로는 AWS WAF가 "봇처럼 보이는" User-Agent를 403으로 막고, 일반 브라우저 헤더로
  위장해야만 통과됨 (robots.txt 정책과 실제 WAF 동작이 모순).
- 위장 후에도 세션당 5~6개 요청 이후부터 JS 토큰 챌린지가 뜨고, 헤드리스 브라우저
  (Playwright)로는 더 강한 "Human Verification" CAPTCHA로 격상됨.
- 대안으로 확인한 rocketpunch.com도 Cloudflare Turnstile 챌린지로 막혀 있음.

CAPTCHA를 뚫으려면 적극적인 봇 탐지 회피가 필요한데, 그건 하지 않기로 했다
(robots.txt가 허용한다고 해서 WAF/CAPTCHA까지 우회하는 건 별개 문제로 판단).

## 결정
데이터 소스를 **한국어 위키백과**(공식 MediaWiki API)로 전환한다.

- 봇 차단이 없고, API 사용이 공식적으로 권장됨 (anonymous 사용도 적절한 속도 제한
  내에서 허용).
- "분류:대한민국의 OO 기업" 하위 카테고리를 라벨로 직접 사용 — thevc.kr의
  knowsAbout/keywords 필드처럼 인포박스를 파싱하는 불안정한 방식보다 안정적.
- 라이선스상 재사용에 문제 없음(CC BY-SA).

## 영향
- 이 샌드박스 환경은 여러 세션이 공유 IP를 쓰는 것으로 보여, 위키백과 API 요청이
  누적 호출량 때문에 429(rate limit)에 걸리는 걸 확인했다. 실제 수집·학습은 이
  환경이 아니라 Kaggle 또는 로컬에서 실행해야 한다.
- 원래 목표였던 "스타트업-투자사 매칭"과는 결이 달라졌지만, "데이터 수집부터
  모델 설계까지 직접 한다"는 핵심 목표는 유지된다.

## 추가 결정 (모델 설계 범위)
단순 지도학습 분류기가 아니라, 2단계로 구성한다:

1. 사전학습(pretrain): 자모 단위 토크나이저로 다음 토큰 예측을 랜덤 초기화부터
   직접 학습 — "내가 만든 언어모델".
2. 미세조정(fine-tune): 1단계에서 직접 사전학습한 모델 위에 산업분야 분류 head를
   얹어 학습. KoBERT 등 외부 사전학습 모델은 쓰지 않는다.

사전학습 유무에 따른 성능 차이를 같은 파라미터 수·같은 데이터로 비교해, 사전학습의
효과를 수치로 보여주는 것이 평가 포인트다.
